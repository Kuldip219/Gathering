## 2. Work completed (chronological)

### 2.1 Foundation fixes
- Fixed a CSS concatenation bug in `accounts/forms.py` — two adjacent string literals in `TEXT_INPUT_CLASSES` had no space, merging `text-sm` and `focus:outline-none` into one invalid class.
- Removed the duplicate `theme/templates/base.html` generated by django-tailwind; the project-level `templates/base.html` is now the single base template using `{% load tailwind_tags %}` + `{% tailwind_css %}`.
- Created the missing templates `accounts/login.html` and `accounts/profile.html` that `accounts/views.py` referenced (previous `TemplateDoesNotExist` crashes).
- Fixed `profile_view` to pass `request.FILES` into `ProfileEditForm` (uploads had been silently dropped).
- Added `requirements.txt`.

### 2.2 Social features: posts, feed, likes
- `posts` app: `Post` (author, image, caption, created_at, newest-first ordering) and `Like` (unique per user+post).
- `PostForm` validates that a post has at least a photo or a caption.
- `home_feed` renders a sticky nav, a family-member avatar row (excluding yourself), post cards with author avatar/name/`timesince`, image, caption, and a Like/Liked toggle with a live count.
- `create_post` view/template for photo + caption.
- `profile.html` rewritten: back-to-feed link, profile header card, logout button, edit-profile form, 3-column posts grid, "+ New post" link.

### 2.3 Email-based authentication
- `User` now uses `email` as `USERNAME_FIELD` (unique); `username` is kept as the display name. Migration `0002_alter_user_email`.
- `LoginForm` relabels Django's `username` field as "Email" and lowercases it in `clean_username`.
- `SignupForm` (email + username + password) lowercases email in `clean_email`.
- `signup_view` + `signup/` route + styled `signup.html`.
- Custom `UserAdmin` so the admin "Add user" form collects email, username and password.

### 2.4 Data restore
- Restored the pre-reset user data (`kuldip86` + their post) from `backup_before_email_auth.json` via `backup_before_email_auth_fixed.json`, backfilling the now-required unique email with the temporary placeholder `kuldip86.restored@placeholder.local`.
- Deleted the throwaway verification superuser.

### 2.5 Google sign-in (django-allauth)
- allauth apps + `django.contrib.sites`, `SITE_ID = 1`, `AUTHENTICATION_BACKENDS`, `SOCIALACCOUNT_PROVIDERS` reading Google credentials from `.env` through `python-dotenv`.
- `SOCIALACCOUNT_AUTO_SIGNUP`, `SOCIALACCOUNT_LOGIN_ON_GET`, `ACCOUNT_EMAIL_VERIFICATION = 'none'`, and `allauth.account.middleware.AccountMiddleware` (required by allauth 65).

## 3. Errors, risks and problems

### 3.1 High priority

**1. `SECRET_KEY` is hardcoded and committed to git.**
`gathering/gathering/settings.py:31` contains the `django-insecure-...` starter key. `manage.py check --deploy` flags it as `security.W009`. Because it is in git history, it must be treated as public.
*Fix:* read `SECRET_KEY` from `.env`/environment with a fail-fast `ImproperlyConfigured` check and generate a new key.

**2. The project cannot be deployed as-is.** `check --deploy` reports 7 warnings:
- `security.W004` — `SECURE_HSTS_SECONDS` unset
- `security.W008` — `SECURE_SSL_REDIRECT` not `True`
- `security.W009` — insecure, auto-generated `SECRET_KEY`
- `security.W012` — `SESSION_COOKIE_SECURE` not `True`
- `security.W016` — `CSRF_COOKIE_SECURE` not `True`
- `security.W018` — `DEBUG = True`
- `security.W020` — `ALLOWED_HOSTS` is empty

Additionally **`STATIC_ROOT` is not defined** anywhere in settings, so `manage.py collectstatic` will fail and the admin/DRF styling will not be served in production. Media (`MEDIA_URL`) is only served by the `urlpatterns += static(...)` block that is active when `DEBUG` is true.
*Fix:* split settings by environment (or gate on an env var): real hosts, `STATIC_ROOT`, secure-cookie/HTTPS flags, and a production media strategy.

**3. The Site-domain data migration bakes the dev host into the database.**
`accounts/migrations/0003_update_site.py` unconditionally sets the Site to `domain='127.0.0.1:8000', name='Gathering'`. That is correct for local dev, but the same migration runs on any fresh production database and will make allauth build password-reset/confirmation links against `127.0.0.1:8000`.
*Fix:* read the domain from an environment variable (falling back to `127.0.0.1:8000` in debug), or set the Site from a deploy step rather than a data migration.

**4. Email is console-only — password reset does not actually deliver mail.**
`EMAIL_BACKEND` is the console backend, so in any non-dev environment users would see nothing and the reset link would only appear in server logs. The `TODO` is in the code but there is no SMTP configuration, no `DEFAULT_FROM_EMAIL`, and no tests/guard.
*Fix:* add env-driven SMTP (host/port/user/password/TLS) and a `DEFAULT_FROM_EMAIL`, keeping console as the debug fallback.

**5. Compiled Tailwind CSS is stale — one class in the new UI is genuinely missing.**
The build at `gathering/theme/static/css/dist/styles.css` is dated **2026-08-05 23:34**, but templates were edited on **2026-08-09** (login page 10:19, new reset templates 10:20). Checking the compiled file directly:

| Class used in templates | In compiled CSS |
|---|---|
| `text-right` (the "Forgot password?" alignment wrapper) | **MISSING** |
| `bg-red-50`, `border-red-100`, `text-red-600`, `ring-teal-500`, `max-w-sm`, `rounded-2xl`, `text-xs` | present |

Because `text-right` is absent, the "Forgot password?" link will not right-align until the stylesheet is rebuilt. Any other new class combinations added since Aug 5 have the same exposure.
*Fix:* `cd gathering && ../.venv/Scripts/python.exe manage.py tailwind build`, and rebuild as part of the workflow whenever templates change.

**6. There are zero automated tests.**
`accounts/tests.py` and `posts/tests.py` are 3-line stubs. The riskiest logic in the project — email-as-username authentication, the case-insensitive social login linking, `toggle_like` and its next-URL guard, and the multi-step allauth password-reset flow (which redirects the key URL to a per-user `…/set-password/` URL in allauth 65) — has no regression coverage.
*Fix:* convert the password-reset verification script (previously run and deleted) into real `TestCase`s, then add tests for signup/login/like.

**7. Sensitive backup files with real user data sit in the working tree.**
`gathering/backup_before_email_auth.json` and `backup_before_email_auth_fixed.json` contain the family's real email addresses and password hashes. They are gitignored but present on disk, and this audit file (and the earlier one) documented a working dev password in plain text.
*Fix:* delete the backups once the restore is confirmed, and never keep plaintext credentials in docs; rotate the dev password if it has been shared.

### 3.2 Medium priority

**8. `adapters.py` can raise `MultipleObjectsReturned`.**
`User.objects.get(email__iexact=email)` in `accounts/adapters.py:19` throws if two accounts differ only by case. SQLite's `unique=True` is case-sensitive, and Google-created accounts never pass through `SignupForm.clean_email`, so `Kuldip@x.com` and `kuldip@x.com` can both exist.
*Fix:* `User.objects.filter(email__iexact=email).first()` (or catch the exception), plus a DB-level `Lower('email')` unique constraint.

**9. `.gitignore` patterns are anchored to the repo root and miss the Django subdirectory.**
The patterns `media/*` and `theme/static/css/dist/` contain slashes, so git anchors them to the repo root — but the real paths are `gathering/media/...` and `gathering/theme/static/css/dist/...`. Verified with `git check-ignore`:

```
git check-ignore -v gathering/media/profile_pictures/         -> not ignored
git check-ignore -v gathering/theme/static/css/dist/styles.css -> not ignored
```

Consequences visible today: the compiled CSS is tracked (and will show up as a changed file on every rebuild), and an uploaded profile picture (`gathering/media/profile_pictures/http___www_pixeljoint.com_files_icons_full_nebula2_02.gif`) is sitting untracked in `git status`. The `PROJECT_AUDIT.md` ignore entry is also stale — that file no longer exists.
*Fix:* change the patterns to `gathering/media/**`, `gathering/theme/static/css/dist/`, drop the stale entry, and decide deliberately whether compiled CSS should be tracked.

**10. No pagination on the home feed.**
`posts/views.py:home_feed` evaluates every `Post` with no limit. Fine with 1 post; degrades as the family posts.
*Fix:* `Paginator` or lazy loading.

**11. Unpinned dependencies.**
`django-allauth`, `python-dotenv`, `PyJWT` and `django-widget-tweaks` have no version pins. allauth 65 already forced a middleware change once, so an unpinned upgrade can break the app silently.
*Fix:* pin all four to the installed versions.

**12. Uploaded images are unvalidated and unsized.**
`User.profile_picture` and `Post.image` are plain `ImageField`s: any Pillow-readable format (the current profile picture is a `.gif` scraped from a website, filename included), no maximum dimensions, no file-size cap, no re-encoding. Phone photos are stored at full size, and replaced images are never deleted from `media/`.
*Fix:* validate content type/size, downscale on save, and clean up orphaned files.

**13. allauth's leftover routes are reachable and unstyled.**
`/accounts/login/`, `/accounts/signup/`, `/accounts/email/`, `/accounts/password/change/` and `/accounts/3rdparty/` all resolve. Visiting them directly shows allauth's bare default templates, which look like a different application than the custom `/login/` and `/signup/` pages.
*Fix:* either style them (they are the missing "change password" and "manage email / Google connection" features) or redirect the auth duplicates to the custom pages.

**14. No UI to change the account email — `kuldip86` is still on a placeholder address.**
`kuldip86.restored@placeholder.local` is not a deliverable mailbox, so their password-reset email would only ever appear in the console. The profile page can edit bio and picture only.
*Fix:* add an "edit email" field (or style allauth's email management view) with case-insensitive uniqueness validation.

**15. No global navigation or logout outside the profile page.**
The feed nav has only "My profile" and "+ New post"; logging out requires opening your own profile first. Session expiry mid-browse gives no obvious escape hatch.
*Fix:* a small account menu in the feed nav.

**16. Input styling is duplicated in three places.**
`accounts/forms.py:TEXT_INPUT_CLASSES`, `posts/forms.py:INPUT_CLASSES`, and a hardcoded `class="..."` inside the allauth override templates. Changing the design means editing all of them.
*Fix:* one shared widget/class constant (or a template include).

**17. File inputs are unstyled.**
`profile.html` renders `{{ form.profile_picture }}` and `create_post.html` renders `{{ form.image }}` as raw browser file inputs, visibly inconsistent with the rest of the cards.
*Fix:* apply the same input classes / a styled label.

**18. `ACCOUNT_EMAIL_VERIFICATION = 'none'` with Google auto-signup.**
Anyone can create an account with any address they type; nothing confirms ownership. Acceptable for a private family app, but it means email is not an identity guarantee.
*Fix:* enable `'optional'`/`'mandatory'` verification once real SMTP exists.

### 3.3 Low priority / cosmetic

**19.** `settings.py` docstring still says "Django 6.0.5"; installed is 6.0.7.
**20.** `STATICFILES_DIRS = [BASE_DIR / "static"]` points at an empty, unused directory — dead config.
**21.** `INTERNAL_IPS = ['127.0.0.1']` is configured but django-debug-toolbar is not installed.
**22.** `TIME_ZONE = 'UTC'` — for a family app in India, displayed dates/times will be UTC; `timesince` is unaffected.
**23.** Console email backend soft-wraps long reset URLs at ~78 characters with `=` continuation markers, so copying the link from the terminal needs the wrapped lines joined. Dev-only artifact; real mail clients decode it transparently.
**24.** No favicon (404 noise) and default unstyled Django 404/500 pages.
**25.** `TEMPLATES` context processors omit `django.template.context_processors.debug`.
**26.** The `!media/.gitkeep` exception in `.gitignore` protects a file that does not exist.
